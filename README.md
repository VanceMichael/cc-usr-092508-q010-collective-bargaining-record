# 集体协商授权与协议形成

记录劳资双方从代表授权、分轮提案到共同协议和履行的过程。

## 参与方与事实

主要参与方包括职工代表、企业代表、工会工作人员、调解人员。领域资料记录以下已经确认的事实：

- 集体协商围绕薪酬待遇和福利保障等现实议题展开
- 协商需要平衡企业经营实际与职工合理诉求
- 换位思考和寻找双方可接纳的平衡点是协商重点

## 业务约束

- 代表授权范围
- 保密成本材料
- 逐轮提案
- 双方确认
- 履行期限
- 签署与撤回并发时不得单方生效
- 重复回执与异步签名幂等归并
- 过程事件只追加不抹除

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/bargaining_context.py` 负责读取和校验这些资料。

`src/bargaining_service.py` 是协商过程服务：保存代表资格、回避关系、成员授权范围、议题、提案、保密成本材料、法律依据、会议轮次和承诺有效期。每次让步引用上一版提案并标明可公开内容；超出授权的条款只暂存待确认；部分议题达成一致先冻结共同条款，最终文本经双方各自确认后才形成协议。服务状态可快照恢复，期限届满或重启后待确认承诺、调解事项和履行节点继续处理，监督人员可从协议条款追溯到授权、提案变化、法律依据和履行结果。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
