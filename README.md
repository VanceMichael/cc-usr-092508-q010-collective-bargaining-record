# 集体协商授权与协议形成

记录劳资双方从代表授权、分轮提案到共同协议和履行的过程。

## 参与方与事实

主要参与方包括职工代表、企业代表、工会工作人员、调解人员。领域资料记录以下已经确认的事实：

- 集体协商围绕薪酬待遇和福利保障等现实议题展开
- 协商需要平衡企业经营实际与职工合理诉求
- 换位思考和寻找双方可接纳的平衡点是协商重点

## 业务约束

- 代表授权范围
- 保密成本材料
- 逐轮提案
- 双方确认
- 履行期限
- 让步引用上一版提案并标明可公开内容
- 超授权条款暂存待确认
- 签署与撤回并发不得单方生效
- 回执与签名幂等归并，异文进入争议
- 过程留痕与监督追溯

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/bargaining_context.py` 负责读取和校验这些资料。

`src/negotiation_service.py` 以事件溯源方式实现协商服务：代表资格与回避、成员授权范围、逐轮提案链、保密材料佐证、共同文本冻结、双方确认与签署、履行节点跟踪。所有变化追加为事件，代表更换、授权收窄、会谈中止与重新开局都不抹去此前过程；服务重启后重放事件日志，继续处理待确认承诺、调解事项与履行节点，并按角色给出下一步、向监督人员提供从协议条款到授权与履行结果的追溯。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
